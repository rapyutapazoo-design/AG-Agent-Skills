# コーディング規約およびセキュリティチェックリスト

このプロジェクト（Kintone、GAS、Webフロントエンド等）における、コミット前の必須チェック項目です。差分（diff）が含まれるファイルに対して、以下の視点でレビューを行ってください。

## 1. セキュリティ（最重要）
*   **認証情報のハードコード禁止**: `token`, `api_key`, `password`, `secret` などの文字列に実際の値が設定されたままコミットされていないか。
*   **環境変数の適切な利用**: 外部APIを利用する場合、キー情報がソースコード内に直書きされていないか。

## 2. Kintoneカスタマイズ・プラグイン
*   **デバッグコードの残存**: `console.log`, `console.warn` などの不要なデバッグ出力が残っていないか（必要なエラーハンドリングとしての `console.error` は許容）。
*   **標準APIの利用**: DOMを直接操作するのではなく、極力Kintoneの標準API（`kintone.app.record.get()` や `kintone.events.on` など）を使用しているか。
*   **非同期処理の戻り値**: イベントハンドラ（`kintone.events.on`）内で非同期処理（`kintone.api` 等）を行う場合、適切に `Promise` を return しているか。

## 3. Google Apps Script (GAS)
*   **実行時間の考慮**: ループ内で重い処理（`SpreadsheetApp.openById` や `UrlFetchApp.fetch` など）を繰り返していないか（N+1問題の警告）。
*   **ログのクリーンアップ**: `Logger.log` などの不要なテスト出力が残っていないか。

## 4. 一般的なコード品質
*   **変数名・関数名**: 意味が分かりやすく、プロジェクトで統一された命名規則（基本はキャメルケース `camelCase`）に従っているか。
*   **不要なコメントのアウト**: コメントアウトされたコードブロックがそのまま放置されていないか。
